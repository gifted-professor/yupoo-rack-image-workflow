# 完整工作流与状态门禁

## 内网人工审核与发布信号

运行 `npm run dashboard -- --host <本机的 Tailscale IPv4> --port 8910` 后，可通过 Tailscale 内网打开商品发布审核台。审核台从现有工作目录实时组装商品卡片，不复制或改写商品事实；人工确认会生成不可变的 approval signal，并写入独立发布队列。

确认信号不等于外部平台已发布。微购相册连接器为 `dry_run_only` 时，队列固定停留在 `APPROVED_WAITING_FOR_CONNECTOR`；只有已启用的真实连接器成功返回外部发布编号，后续发送器才可以把任务标为已发布。小红书使用独立目的地状态与文案预览，未接入前保持 `PLANNED`。

## 最终交付物

每个 SKU 固定交付：

1. 生成的正面实体货架图，含准确价格牌。
2. 生成的反面实体货架图，含准确价格牌。
3. 生成的实体店试穿主图，展示自然上身版型。
4. 生成的实体店试穿近景，展示领口、Logo、面料、袖口和下摆。
5. Yupoo 原始详情图，按领口/腰头、Logo、袖侧、下摆车线、面料拼接、洗标吊牌、口袋或拉链等真实内容排序。

试穿图只改变人物、姿势和门店呈现，不得改变商品事实。Yupoo 缺少真实背面或关键背部细节时，状态必须是 `BLOCKED_NO_BACK_DETAILS`，不能猜。

## 流程

### 背面试穿构图

`tryon_back` 不再使用“手机贴在后脑、手臂绕到身后”的不自然自拍。默认 `composition` 为 `companion_rear`：由同行者从后方拍摄，模特自然背对镜头、双臂放松、手机不入镜。需要生活方式画面时可设为 `side_mirror_reflection`，前景人物正常侧身自拍，旁边一面全身镜完整显示同一个人的后背；`pose_reference` 只控制人物、镜子和相机位置，绝不能提供商品款式、颜色、Logo、文字或图案。

背面审核除商品结构外，还必须检查前景与镜中人物动作一致、没有重复人物或肢体、镜中商品没有变款，并确认手机未出现在后脑附近。

```text
Yupoo 相册
  ↓ 下载原图、提取 SKU 与候选拿货价
编号宫格图
  ↓ 人工确认正面、反面、Logo、结构细节与颜色基准
商品事实与发布草稿
  ↓ 同一份事实同时服务标题、价格、图片提示词和后续发布
正反面参考包
  ↓ 每张：门店 1 + 空白牌 1 + 商品图不超过 3
CPA 并发生成（默认 4：货架正反面 + 试穿主图/近景）
  ↓ 只写入 review
颜色与款式 QA
  ├─ 不合格 → REPAIR_REQUIRED → 定点修复 → 再检查
  ├─ 货架图合格 → APPROVED_FOR_PRICE → 确定性价格牌程序
  └─ 试穿图合格 → APPROVED_FOR_PUBLISH → 原样输出
  ↓
outputs 正反面货架成品 + 两张试穿图 + Yupoo 详情原图
```

## 商品事实与发布草稿

`run` 会在 `work/items/<SKU>/` 下生成：

- `product-facts.json`：商品事实的单一来源；没有证据的季节、材质、功能和场景保持为空。
- `publish-draft.json`：由商品事实确定性拼装标题、简称、价格、标签和图片顺序。

发布草稿默认状态为 `DRAFT_REVIEW`，并保留图片未审核、成本未确认或事实未确认等 blocker。后续只有图片和发布资料全部通过检查，才能升级为 `READY_TO_PUBLISH`。

`prepare-publish` 会把 `finalize-summary.json`、`publish-draft.json` 和 Yupoo `manifest.json` 合并。只有正反面货架图完成写价、两张试穿图完成款式 QA、所有 blocker 已清除且上传图片真实存在时，才生成 `READY_TO_PUBLISH` 商品包；上传顺序固定为正面货架图、反面货架图、试穿主图、试穿近景、Yupoo 原图。

`scripts/upload-szwego.mjs --dry-run` 是微购相册上传前的只读门禁。它会展开标题、价格、标签、颜色/尺码规格、库存、运费和图片顺序，检查所有文件真实存在，并确认五张生成图都来自已审批的最终输出。dry-run 不登录、不上传文件、不填写网页、不点击发布；`DRAFT_REVIEW`、任何 blocker 或 `REVIEW_PENDING` 都会得到 `DRY_RUN_BLOCKED`。正式浏览器上传仍必须保留最后一次人工确认。

审核台中的正反货架图在最终确认前就显示确定性写价的页面预览，运营不再看到空白橙牌；预览不等于批准。用户点击“确认、写价并加入发送队列”后，服务再次从当前审核源图生成正式价格成品并重新组装 `publish-package.json`。只有正面和背面的 `price_display.rendered_views` 都存在、写入价格与商品销售价完全一致且五张成品齐全时，才允许产生发送队列事件；任何空白价格牌都会以 `*_PRICE_SIGN_NOT_RENDERED` 阻断。

发布默认值来自 `config/publishing.json`：

- 每个颜色/尺码组合库存为 10。
- 运费模板为“全国统一运费 10 元”，运费 10 元。
- 尺码优先从人工事实读取；为空时可从 Yupoo 标题的 `S-XXL` 等范围展开。
- 颜色必须来自 Yupoo 明文、官方同款页面或人工确认，不能从色号猜颜色名。
- 标签只匹配微商相册中已经存在的标签；未命中的标签不会自动创建。
- 清晰的模特正面、背面和结构特写可以作为货架图商品参考；只有在正反面或关键结构事实不足时，才标记 `SKIP_UNUSABLE_REFERENCES`。

## 输入门禁

| 状态 | 含义 | 后续动作 |
|---|---|---|
| `BLOCKED_UNCONFIRMED_COST` | 从标题检测到价格，但人还没确认是拿货价 | 不写价格 |
| `BLOCKED_NO_BACK_DETAILS` | 没有足够的真实背面证据 | 不生成反面 |
| `SKIP_UNUSABLE_REFERENCES` | 缺少清晰正面、背面或关键结构证据 | 跳过 SKU |
| `READY` | 正面或反面参考包完整 | 可以进入生成队列 |

## 输出门禁

| 状态 | 含义 | 是否写价格 |
|---|---|---|
| `REVIEW_PENDING` | 刚生成，尚未检查 | 否 |
| `REPAIR_REQUIRED` | 有色差或结构错误 | 否 |
| `APPROVED_FOR_PRICE` | 六项 QA 全部通过 | 是 |
| `APPROVED_FOR_PUBLISH` | 试穿图商品与人体 QA 全部通过 | 否，原样进入 outputs |

## 六项 QA

1. 视角：正面和反面没有混淆。
2. 颜色：主商品及后排重复商品与 `color_authority` 色相、饱和度、明度一致。
3. Logo：位置、方向、尺寸、数量正确。
4. 结构：领口、袖口、下摆、口袋、拉链、拼接线没有增删或变形。
5. 价格牌：真实安装在货架上，橙色上联、黑色下联完全空白。
6. 场景：像普通手机在有库存的门店里拍摄，无水印、伪文字、人物或人体模特。

试穿图另做六项检查：颜色、Logo/图案、服装结构、人体穿着关系、成年人物结构、实体门店手机感。任一项失败都进入 `REPAIR_REQUIRED`，不能直接发布。

## 定价

当前规则：

```text
最低目标价 = 拿货价 / 0.6
最终卖价 = 不低于最低目标价的、最小的以 9 结尾价格
```

示例：

- 135 / 0.6 = 225 → 229
- 60 / 0.6 = 100 → 109

价格牌只显示：`门店特惠`、`¥价格`、品类中文和英文。不显示建议零售价或折扣率。

## 并发策略

- 新生成图统一保存为竖版 `1080 × 1440`（宽:高 `3:4`）；构图提示先保留四周安全空间，确定性归一化只做完整主体缩放与模糊背景延展，不裁掉关键内容。
- 正式初始值：全局并发 4。
- 同一 SKU 的货架正面、货架反面、试穿主图、试穿近景四张同时生成。
- 修复队列与首轮生成队列分开，建议并发 3。
- 请求失败可以重试；商品事实检查失败不能靠重试自动放行。
