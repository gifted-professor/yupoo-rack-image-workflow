# 已确认决策

这份文件记录当前业务口径。修改流程前先核对，避免以后又回到已经否定过的方案。

1. 商品图只从 Yupoo 相册取证，不再按货号去 Nike 或 Adidas 官网补图。
2. AI 只生成正面实体货架图和反面实体货架图。
3. 领口、Logo、面料、车线、洗标、口袋等详情直接使用 Yupoo 原图，不生成新的细节实拍。
4. 先把相册做成编号宫格，人工或视觉模型分类正面、反面和细节；分类结果需要人工确认。
5. 门店场景参考使用真实 Nike/Adidas 门店照片，目标是有库存、普通手机实拍感，不是空展厅或广告棚拍。
6. 商品颜色从第一次生成就锁定到指定 Yupoo `color_authority`；生成后仍必须做色差检查。
7. 价格牌必须是货架上的真实物理结构。AI 生成空白橙色上联和黑色下联，准确文字与价格后写。
8. 价格牌不使用悬浮贴纸、不使用绿色小吊牌作为默认成品，不显示建议零售价。
9. 定价规则为拿货价除以 `0.6`，再向上取以 9 结尾的价格：135 → 229，60 → 109。
10. CPA 首个生产并发值为 4；同一 SKU 正反面并发，修复任务进入单独队列。
11. 请求成功不等于图片合格。色差或款式错误必须标记 `REPAIR_REQUIRED`，修复后重新检查。
12. 只有 `APPROVED_FOR_PRICE` 能写价格和进入 `outputs`；人工检查是最终放行门。
